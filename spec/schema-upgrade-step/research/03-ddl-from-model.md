# 03 — DDL from the model

Evidence: SQLAlchemy 2.0.50 (the floor), SQLite 3.53.1, against a copy of a 2.8.3-created SQLite
database (and a variant with `source` dropped to model an untouched 2.8 DB). PostgreSQL is compiled
offline with `postgresql.dialect()` only; nothing was executed against a PG server.

## Recommendation

1. **Add columns from the model with `CreateColumn`.** For each model column absent from
   `inspect(conn).get_columns(t.name, schema=t.schema)`, emit
   `ALTER TABLE {prep.format_table(t)} ADD COLUMN {CreateColumn(c).compile(dialect=conn.dialect)}`
   (`prep = conn.dialect.identifier_preparer`). This needs no per-column code, renders the UUID variant
   correctly per dialect, quotes `"group"`-style names, and `format_table` honours
   `Entity.__table_args__['schema']` (`hs.task`, `"My Schema".task`).
2. **Give `part` a server default:** `mapped_column(INTEGER, nullable=False, default=0,
   server_default=text('0'))`. It renders `DEFAULT 0` on both dialects. `server_default='0'` renders
   `DEFAULT '0'`, which works (SQLite coerces it to integer 0, and PG casts it) but reads worse;
   `literal(0)` renders identically to `text('0')` and adds nothing. Keep `default=0`. On a fresh DB the
   only change to `create_all` output is `part INTEGER DEFAULT 0 NOT NULL`, which is harmless.
3. **Refuse unsafe columns before any DDL** (rules below). Today's delta passes them all once
   `part` has its server default.
4. **Indexes:** diff by name and emit `CreateIndex(ix, if_not_exists=True)`. **Tables:** emit
   `CreateTable(t, if_not_exists=True)` plus that table's indexes, not `create_all`. Both are
   idempotent under a race and fit the same plan/apply loop.
5. **R5:** drop `unique=True` from `previous_id`/`next_id`, and add
   `index_tasks_previous_id` / `index_tasks_next_id` beside the other `index_tasks_*`.
   **R6:** on PG only, drop reflected unique constraints on exactly `['previous_id']` / `['next_id']`.
   **R7:** on SQLite, skip that step by dialect.
6. **Atomicity (a finding the plan must act on):** under the default pysqlite driver, DDL inside
   `engine.begin()` is **not transactional**. An `ALTER TABLE … ADD COLUMN` survived a rollback
   (verified). Issuing `conn.exec_driver_sql('BEGIN IMMEDIATE')` first on the SQLAlchemy connection
   makes the DDL roll back and commit correctly (verified both ways). It also takes the write lock, so
   a concurrent upgrader waits and then re-inspects (R3). On PG, DDL is transactional; take
   `pg_advisory_xact_lock(<const>)` before inspecting so two upgraders serialize (see Needs CI).

## Compiled DDL evidence

`CreateColumn` for the 2.8→develop delta (current model), via `format_table`:

```
sqlite     ALTER TABLE task ADD COLUMN source TEXT
postgresql ALTER TABLE task ADD COLUMN source UUID
sqlite     ALTER TABLE task ADD COLUMN fingerprint TEXT
postgresql ALTER TABLE task ADD COLUMN fingerprint TEXT
sqlite     ALTER TABLE task ADD COLUMN part INTEGER NOT NULL              # today: refused by SQLite
postgresql ALTER TABLE task ADD COLUMN part INTEGER NOT NULL              # today: fails on rows
# with server_default=text('0'), both dialects:
           ALTER TABLE task ADD COLUMN part INTEGER DEFAULT 0 NOT NULL
```

`CreateColumn` renders **no** table-level constraints inline. `previous_id` (unique=True) → `previous_id
TEXT|UUID`. `id` (PK) → `id TEXT NOT NULL`, and an Integer PK on PG → `SERIAL NOT NULL`. A
`ForeignKey` column → `fk TEXT`, with no `REFERENCES`. So unique, PK and FK intent would be **silently
lost**, which is why those columns are refused rather than added. `Identity()` → SQLite
`INTEGER NOT NULL`, PG `GENERATED BY DEFAULT AS IDENTITY`. `Computed` → `GENERATED ALWAYS AS (…)`
(`STORED` on PG).

SQLite, run against the 2.8.3 copy with two rows:

```
ADD COLUMN part INTEGER DEFAULT 0 NOT NULL   -> OK, existing rows (0,'integer')
ADD COLUMN part INTEGER DEFAULT '0' NOT NULL -> OK, existing rows (0,'integer')
ADD COLUMN part INTEGER NOT NULL             -> Cannot add a NOT NULL column with default value NULL
ADD COLUMN source TEXT                       -> OK, existing rows NULL
```

Indexes and tables (identical on both dialects except types):

```
CREATE INDEX IF NOT EXISTS index_tasks_source ON task (source, fingerprint)
CREATE INDEX IF NOT EXISTS index_tasks_previous ON hs.task (previous_id)   -- schema-qualified table
CREATE TABLE IF NOT EXISTS source (id UUID NOT NULL, …, PRIMARY KEY (id))  -- PG; TEXT on SQLite
ALTER TABLE hs.task DROP CONSTRAINT IF EXISTS task_previous_id_key       -- DropConstraint(uc, if_exists=True)
```

R5, after the change: `CreateTable(Task)` ends `PRIMARY KEY (id)\n)` on both dialects, with **no
`UNIQUE`**, plus:

```
CREATE INDEX index_tasks_next_id ON task (next_id)
CREATE INDEX index_tasks_previous_id ON task (previous_id)
CREATE INDEX index_tasks_retries ON task (exit_status, retried)
CREATE INDEX index_tasks_source ON task (source, fingerprint)
CREATE INDEX index_tasks_unscheduled ON task ("group", schedule_time)
```

A fresh SQLite DB built from that shape has `get_unique_constraints('task') == []`; its only autoindex is
`sqlite_autoindex_task_1`, the TEXT primary key. Before the change, the 2.8-era output on PG is the same
table with `UNIQUE (previous_id), UNIQUE (next_id)` as unnamed table constraints. The metadata
`naming_convention` only covers `ix`, so PG assigns the names itself (by its default scheme,
`task_previous_id_key` / `task_next_id_key`). Discover them rather than hard-coding them.

Prototype (generic diff + apply, ~30 lines) on the 2.8.3 copy: run 1 added 3 columns and 3 indexes
(plus `source` and `index_source_lookup` on the untouched variant). Run 2 made **0 changes**. Old rows read
`part=0, source=None, tag={'part': 0}` (tag untouched, R2), and the SQLite UNIQUE constraints remain (R7).

## Refusal rules

Check every missing column before emitting any DDL. Each check is a `Column` attribute, so it works
for any future column.

| Condition | Detection on `Column` | Error it prevents |
|---|---|---|
| NOT NULL, no DB-side default | `not c.nullable and c.server_default is None` (PK/identity are caught first) | SQLite: `Cannot add a NOT NULL column with default value NULL`; PG: `column … contains null values` on a non-empty table |
| Primary key | `c.primary_key` | SQLite: `Cannot add a PRIMARY KEY column`; `CreateColumn` drops the PK anyway |
| Unique | `c.unique` (also `Index(unique=True)` on a missing column) | SQLite: `Cannot add a UNIQUE column`; `CreateColumn` silently omits it |
| Foreign key | `c.foreign_keys` | `REFERENCES` silently omitted; SQLite (FKs on): `Cannot add a REFERENCES column with non-NULL default value` |
| Generated | `c.computed is not None or c.identity is not None` | SQLite: `cannot add a STORED column`; Identity becomes `INTEGER NOT NULL` → NOT NULL error |
| Non-constant default | `c.server_default` is not a plain literal (`str`, or `TextClause` matching a number / quoted string / NULL / TRUE / FALSE) | SQLite: `Cannot add a column with non-constant default` (`CURRENT_TIMESTAMP`, `(1+1)`; `(0)` is accepted) |

All errors above were reproduced on SQLite 3.53.1. The R4 minimum is row 1. Rows 2–6 are a few lines
each, and they turn silent schema drift or a raw `OperationalError` into the same actionable message:
`cannot upgrade table 'task': column 'x' (<reason>) can't be added in place`. Raise one exception type,
caught where `ensuredb` already reports `DatabaseUninitialized`.

## Index & constraint handling

- **Missing indexes:** compare `{ix.name for ix in t.indexes}` with
  `{i['name'] for i in insp.get_indexes(t.name, schema=t.schema)}`. On SQLite, `get_indexes` **omits**
  `sqlite_autoindex_*` (verified: the 2.8 DB lists only the two named indexes). On PG it **includes**
  the unique indexes that back constraints, marked `duplicates_constraint` (SQLAlchemy PG reflection
  docs). Those are extra names and harmless for a "missing" diff.
- **`create_all` does not repair existing tables:** run against the 2.8 copy, it returned OK and
  created no `index_tasks_source`. It only creates indexes for tables it creates. Keep `create_all`
  for fresh DBs (initdb/truncate); the upgrade step must do the index diff itself.
- **R6 (PG):** after `insp.get_unique_constraints('task', schema=…)`, drop each entry whose
  `column_names` is exactly `['previous_id']` or `['next_id']` using `ALTER TABLE {fmt} DROP CONSTRAINT
  IF EXISTS {prep.quote(name)}` (or `DropConstraint(UniqueConstraint(…, name=name), if_exists=True)`).
  Log INFO naming the table. Then the generic index diff creates the R5 indexes. This is the only
  named special case: key it on "the model no longer declares uniqueness on these columns", not on
  the PG name.
- **R7 (SQLite):** the 2.8 DB reflects `[{'name': None, 'column_names': ['previous_id']}, {'name': None,
  'column_names': ['next_id']}]`. A nameless constraint can't be dropped, and SQLite can't drop
  constraints anyway, so skip by `dialect.name == 'sqlite'` and log DEBUG at most.
- **A user-made unique *index* on PG** (not a constraint) would show in `get_indexes` with
  `unique=True` and no `duplicates_constraint`. 2.8 never created one. Note it in TECH and don't
  handle it.

## Algorithm sketch

```
def upgrade_schema(engine):
    with engine.connect() as conn:
        lock(conn)    # sqlite: BEGIN IMMEDIATE; postgresql: SELECT pg_advisory_xact_lock(K)
        insp, prep, plan = inspect(conn), conn.dialect.identifier_preparer, []
        for t in Entity.metadata.sorted_tables:
            if not insp.has_table(t.name, schema=t.schema):
                plan += [CreateTable(t, if_not_exists=True)]
                plan += [CreateIndex(ix, if_not_exists=True) for ix in t.indexes]
                continue
            have = {c['name'] for c in insp.get_columns(t.name, schema=t.schema)}
            for c in (c for c in t.columns if c.name not in have):
                if reason := unsafe(c):                  # refusal table; nothing executed yet
                    raise SchemaUpgradeError(t.name, c.name, reason)
                plan += [text(f'ALTER TABLE {prep.format_table(t)} ADD COLUMN '
                              f'{CreateColumn(c).compile(dialect=conn.dialect)}')]
            if conn.dialect.name == 'postgresql':        # R6, the one named case
                for uc in insp.get_unique_constraints(t.name, schema=t.schema):
                    if uc['name'] and uc['column_names'] in (['previous_id'], ['next_id']) \
                            and not t.c[uc['column_names'][0]].unique:
                        plan += [drop_constraint(t, uc['name'])]
            have_ix = {i['name'] for i in insp.get_indexes(t.name, schema=t.schema)}
            plan += [CreateIndex(ix, if_not_exists=True) for ix in t.indexes if ix.name not in have_ix]
        for step in plan: log.info(describe(step)); conn.execute(step)   # names the table
        conn.commit()                                     # empty plan: nothing above DEBUG
```

## Needs CI (PG)

- Executing `ADD COLUMN part INTEGER DEFAULT 0 NOT NULL` on a populated `task`. PG docs (ALTER TABLE,
  PG 11+): a non-volatile `DEFAULT` is stored in the catalog and applies to existing rows with no rewrite.
  Without a default on a non-empty table, the error is `column "part" … contains null values`.
- The actual auto-generated constraint names (`task_previous_id_key` / `task_next_id_key` expected)
  and their reflection through `get_unique_constraints`, including with `config.database.schema` set.
- `DROP CONSTRAINT IF EXISTS` + `CREATE INDEX IF NOT EXISTS` idempotence on a second run, and
  `duplicates_constraint` entries disappearing after the drop.
- Two concurrent upgraders under `pg_advisory_xact_lock`. Without the lock, `ADD COLUMN` races to
  `column already exists`, and concurrent `CREATE TABLE IF NOT EXISTS` can still hit a `pg_type`
  unique violation. `ADD COLUMN IF NOT EXISTS` (PG 9.6+) is a fallback, but the lock is simpler and
  covers every statement.
- UUID variant on PG: `source UUID` must accept the reserved-source UUIDv7 ids that 2.9 writes.
